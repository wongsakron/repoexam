# บทที่ 5 การวิเคราะห์และออกแบบระบบ
> เล่ม 2 หน้า 201–218 · ตรงกับหลักสูตรกรมที่ดินข้อ "วิเคราะห์ ออกแบบระบบงานคอมพิวเตอร์" โดยตรง ⭐

## 1. ระบบ & การวิเคราะห์ระบบ (น.201)
- **ระบบปิด (Closed)** ควบคุม/แก้ไขตัวเองอัตโนมัติ · **ระบบเปิด (Open)** ต้องมีมนุษย์ควบคุม
- **System Analysis** = ศึกษาปัญหาระบบปัจจุบันเพื่อออกแบบระบบใหม่/ปรับปรุงระบบเดิม
- **System Design** = วางแผนพัฒนาระบบใหม่ (โปรแกรม + ฐานข้อมูล) ใช้ DFD วิเคราะห์ Input–Process–Output
- วงจร **SDLC**: Planning → Analysis → Design → Implementation → Testing → Deployment → Maintenance

## 2. DFD – Data Flow Diagram (น.201–206) ⭐
- สัญลักษณ์ 4 อย่าง: **External Entity** (สิ่งภายนอก/บุคคล/หน่วยงาน) · **Process** (กระบวนการ) · **Data Store** (แหล่งเก็บข้อมูล) · **Data Flow** (ลูกศร)
- **กฎการตั้งชื่อ**: Process = **คำกริยา** (พิมพ์ใบเสร็จ, คำนวณราคา) · Entity/Data Store/Data Flow = **คำนาม** (ลูกค้า, ข้อมูลลูกค้า)
- **กฎการเขียน**:
  1. Process ต้องมีทั้งข้อมูลเข้าและข้อมูลออก
  2. **Data Store → Data Store ตรงๆ ไม่ได้** ต้องผ่าน Process
  3. **Entity ↔ Data Store ตรงๆ ไม่ได้** ต้องผ่าน Process
  4. Data Flow ทุกเส้นต้องมีชื่อกำกับ (คำนาม) และไหลทิศทางเดียว
- **Context Diagram (DFD Level 0)**: มี **Process เดียว หมายเลข 0** ชื่อเป็นชื่อระบบ · **ไม่แสดง Data Store** · อยู่ในหน้าเดียว
- **Level 1**: แตกเป็น Process หลัก (เลข 1, 2, 3…) · คง Entity เดิมทั้งหมด · เพิ่ม Data Store ได้ · ยิ่งระดับสูงยิ่งละเอียด
- ขั้นตอน: หา Entity → Context Diagram → วิเคราะห์ข้อมูล → วิเคราะห์ Process → เขียน DFD ระดับต่างๆ

## 3. ER-Diagram (น.206–210) ⭐
- **Entity** = สี่เหลี่ยมผืนผ้า (ชื่อรวม เช่น "สัตว์เลี้ยง") · **Attribute** = วงรี (หัวคอลัมน์) · **Relationship** = สี่เหลี่ยมข้าวหลามตัด
- (เสริม) Key Attribute ขีดเส้นใต้ · Multi-valued = วงรีเส้นคู่ · Derived = วงรีเส้นประ · Composite = วงรีแตกย่อย
- Cardinality: **1:1** (เลขบัตรประชาชน–บุคคล, IP–เครื่อง) · **1:N** (อาจารย์ที่ปรึกษา–นักศึกษา) · **M:N** (นักศึกษา–วิชา)
- **Degree ของความสัมพันธ์**: **Unary/Recursive** (เอนทิตีเดียวกัน เช่น พนักงาน "เป็นหัวหน้า" พนักงาน) · **Binary** (2 เอนทิตี พบมากสุด) · **Ternary** (3 เอนทิตี เช่น ผู้ขาย–ชิ้นส่วน–คลังสินค้า "จัดส่ง")

## 4. การบริหารจัดการโครงการ (น.210–213)
- **Waterfall**: ทำทีละขั้นต่อเนื่อง (Requirement → Design → Implementation → Testing → Deployment → Maintenance) · ชัดเจน คุมความเสี่ยงได้ · **ยืดหยุ่นต่ำ** ส่งมอบช้า → ใช้เมื่อความต้องการชัดเจนไม่เปลี่ยน
- **Agile**: ทำเป็นรอบสั้น (Iterative & Incremental) **Sprint 2–4 สัปดาห์** · User Stories · **Daily Standup ~15 นาที** · Review & Retrospective · ส่งมอบต่อเนื่อง → ใช้เมื่อความต้องการเปลี่ยนบ่อย
- **Scrum** (Agile แบบ Sprint) · **Kanban** (บอร์ดแสดงสถานะงาน) · **Lean** (ลดความสูญเปล่า) · **PRINCE2** (บทบาทชัด คุมความเสี่ยง) · **CPM** (เส้นทางวิกฤต) · **Six Sigma** (สถิติลดความผิดพลาด)

## 5. Digital Transformation (น.214–218)
- **Change** = เปลี่ยนเล็ก–ใหญ่ต้องคุมต่อเนื่อง · **Transformation** = ปฏิรูปขนานใหญ่ถาวร
- DX = นำเทคโนโลยีดิจิทัลมาเปลี่ยนองค์กรทั้งระบบ เพื่อไม่ให้ถูก **Digital Disruption**
- ประโยชน์ต่อภาครัฐ: บริหาร/บริการแม่นยำ · ประชาชนเข้าถึงง่าย (ยื่นออนไลน์ นัดหมาย ชำระดิจิทัล) · ใช้ข้อมูลกำหนดนโยบาย · ราชการคล่องตัว
- กระบวนการ 7 ขั้น: ประเมินความพร้อม (SWOT, Digital Maturity) → วิสัยทัศน์/เป้าหมาย → **BPR** ออกแบบกระบวนการใหม่ → เลือกเทคโนโลยีคุ้มค่า (Cloud, Big Data, AI, IoT, RPA) → **Change Management** → นำร่อง (Pilot) → วัดผลปรับปรุงต่อเนื่อง
- ประเด็นสำคัญ: DX ≠ ใช้เทคโนโลยีอย่างเดียว · **คนคือหัวใจ** (Digital Literacy/Mindset) · Digital ไม่ใช่คำตอบเสมอ · **Data Governance** · **Cybersecurity ต้องมาก่อน** · ผู้นำดิจิทัล · มี **KPIs**
