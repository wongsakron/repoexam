# บทที่ 3 ฐานข้อมูล (Database)
> เล่ม 2 หน้า 116–144 · บทหลักของสายนักวิชาการคอม ออกทั้ง ER, คีย์, SQL, ACID/CAP, NoSQL

## 1. ข้อมูล vs สารสนเทศ (น.116)
- **ข้อมูล (Data)** = ข้อเท็จจริงดิบ เช่น ชื่อ เลขบัตร คะแนนแต่ละคน
- **สารสนเทศ (Information)** = ข้อมูลที่ **ผ่านการประมวลผล** แล้วใช้ตัดสินใจได้ เช่น เกรดเฉลี่ย รายงานสรุป
- ฐานข้อมูล = ที่เก็บข้อมูล + ความสัมพันธ์ระหว่างข้อมูล ควบคุมโดย **DBMS**

## 2. ลำดับชั้นข้อมูล (Data Hierarchy) (น.123)
- **Bit → Byte (1 ตัวอักษร) → Field (เขตข้อมูล) → Record (ระเบียน) → File/Table (แฟ้ม) → Database**
- คำเรียกที่ตรงกัน: **Table = Relation = Entity = File** · **Row = Tuple = Record** · **Column = Attribute = Field**
- View = Query = ตารางเสมือนสำหรับรายงาน

## 3. ความสัมพันธ์ (Relationship) (น.124–125)
- **1:1** โรงเรียน–ผู้อำนวยการ
- **1:N** ครูที่ปรึกษา–นักเรียน, โรงเรียน–นักเรียน
- **M:N** นิสิต–วิชาที่ลงทะเบียน, สมาชิก–หนังสือที่ยืม (ต้องมีตารางกลางเชื่อม)

## 4. คีย์ (Key) (น.126–128) ⭐
- **Super Key** = แอททริบิวต์/กลุ่มที่แยกทูเพิลได้ไม่ซ้ำ
- **Candidate Key** = คีย์ที่มีคุณสมบัติพอจะเป็นคีย์หลัก
- **Primary Key** = ไม่ซ้ำ (Unique) + **ห้ามว่าง (NOT NULL)** + ไม่ควรเปลี่ยน + มีได้ 1 ตัวต่อตาราง
- **Foreign Key** = คีย์ที่อ้างถึง PK ของตารางอื่น → ใช้ **เชื่อมความสัมพันธ์**
- **Composite Key** = PK ที่รวมหลายแอททริบิวต์ · **Alternate Key** = Candidate ที่ไม่ได้ถูกเลือก · **Secondary Key/Index** = ช่วยค้นหา/เรียงเร็ว

## 5. ข้อดีของฐานข้อมูลเชิงสัมพันธ์ (น.128–131)
- **Data Integrity** 3 แบบ: Static (กฎข้อมูล เช่น อายุติดลบไม่ได้) · Dynamic/State Transition (ลำดับเปลี่ยนสถานะ โสด→หมั้น→แต่งงาน) · General (กฎเรื่องคีย์)
- **Data Independence**: Physical (เปลี่ยนโครงสร้างจัดเก็บไม่กระทบโปรแกรม) · Logical (เปลี่ยนความสัมพันธ์ไม่กระทบโปรแกรม)
- **Recovery**: System failure (ไฟดับ) = **Soft Crash** · Media failure (ดิสก์เสีย) = **Hard Crash**
- **Concurrency Control** = คุมหลายธุรกรรมเข้าถึงพร้อมกัน · **Deadlock** = ต่างรอปลดล็อกกัน → ยกเลิกธุรกรรมหนึ่ง + Rollback
- ลดความซ้ำซ้อน (Redundancy) · เลี่ยงความขัดแย้ง (Inconsistency) · ใช้ร่วมกันได้ · กำหนดมาตรฐาน/ความปลอดภัย (DBA)
- แก้ข้อมูลที่มี FK อ้างอิง: **CASCADE** ไล่แก้ต่อทอด · **RESTRICT** ไม่ยอมให้แก้/ลบ · **NO ACTION** ไม่ทำอะไรเพิ่ม
- ข้อเสีย RDB: แพง ช้าเมื่อข้อมูลมาก ขยายแบบแนวตั้ง (Scale Up) ไม่ยืดหยุ่น รวมศูนย์เสี่ยงล่ม

## 6. ภาษา SQL (น.131–134) ⭐
- `SELECT ฟิลด์ FROM ตาราง WHERE เงื่อนไข` — ดึงข้อมูล (* = ทุกคอลัมน์)
- `INSERT INTO ตาราง (ฟิลด์...) VALUES (ค่า...)` — เพิ่มแถว (ลำดับค่าต้องตรงฟิลด์, ฟิลด์ที่ไม่ใส่ = NULL)
- `UPDATE ตาราง SET ฟิลด์=ค่า WHERE ...` — แก้ไข (**ลืม WHERE = แก้ทุกแถว**)
- `DELETE FROM ตาราง WHERE ...` — ลบแถว
- กลุ่มคำสั่ง: **DDL** (CREATE/ALTER/DROP) · **DML** (SELECT/INSERT/UPDATE/DELETE) · **DCL** (GRANT/REVOKE)
- `LIKE '%abc%'` ค้นคำที่อยู่ตรงไหนก็ได้ · `ORDER BY` เรียง · `JOIN` รวมตาราง · `COUNT/SUM/AVG/MAX/MIN`

## 7. คุณลักษณะที่ดี & องค์ประกอบ DBMS (น.134–137)
- คุณลักษณะที่ดี: Minimum Redundancy · Maximum Integrity · Data Independence · High Security · Centralized Control
- องค์ประกอบ: Software · Hardware · Data · Procedures · Database Access Language · **Query Processor** (แปลคำสั่ง) · Run-time DB Manager (คุม Consistency/Integrity/Security) · Data Manager · Database Engine · **Data Dictionary** (เก็บ Metadata: ชื่อตาราง ชนิด ขนาด) · Report Writer · Users
- บุคลากร: **DBA** (ติดตั้ง DBMS, จัดสรรดิสก์, สร้างโครงสร้าง, **Backup/Recovery**, Tuning, ความปลอดภัย) · System Analyst · Programmer · End User

## 8. ความปลอดภัย & การปกป้องข้อมูล (น.138–140)
- **Discretionary Control** = กำหนดสิทธิ์รายผู้ใช้–รายวัตถุ (ยืดหยุ่น)
- **Mandatory Control** = วัตถุมี Classification Level ผู้ใช้มี Clearance Level (ลดหลั่นตามชั้น)
- เก็บข้อมูลเท่าที่จำเป็น: Adequate · Relevant · Limited to what is necessary (สอดคล้อง PDPA)

## 9. ประเภทฐานข้อมูลอื่น (น.117–122, 140–141)
- **NoSQL** แก้ปัญหา RDB 3 ข้อ: ข้อมูลไม่มี/กึ่งโครงสร้าง (JSON/XML) · ขยายแนวนอน (**Scale Out** เพิ่มเซิร์ฟเวอร์) · อ่านข้อมูลมหาศาลเร็ว
  - Key-Value (Redis, DynamoDB – ตะกร้าสินค้า เกม) · Document (MongoDB – JSON) · Wide-Column (Cassandra, HBase) · Graph (Neo4j – Social Network) · In-Memory (Redis – เร็ว แต่ไฟดับหาย)
- **Distributed DB**: Homogeneous (OS/DB เหมือนกันทุกที่) vs Heterogeneous
- **Cloud DB**: AWS, Azure, Google Cloud SQL
- **Hierarchical** = ต้นไม้ พ่อ–ลูก (ลูกมีพ่อได้ตัวเดียว) · **Network** = เครือข่าย แสดงความสัมพันธ์ชัดเจน

## 10. CAP Theorem & ACID (น.141–143) ⭐
- **CAP** เลือกได้ 2 ใน 3: **C**onsistency (อ่านได้ข้อมูลล่าสุดตรงกันทุกโหนด) · **A**vailability (พร้อมใช้เสมอ) · **P**artition tolerance (โหนดขาดยังทำงานได้)
  - RDBMS ส่วนใหญ่ = **CA** · NoSQL มักเป็น **AP** หรือ **CP**
- **ACID** (คุณสมบัติธุรกรรมของ RDBMS):
  - **Atomicity** ทำสำเร็จทั้งหมดหรือไม่ทำเลย (โอนเงินตัด A แล้วต้องเพิ่ม B)
  - **Consistency** ข้อมูลถูกต้องสอดคล้องหลังธุรกรรม
  - **Isolation** ธุรกรรมพร้อมกันไม่ทับซ้อนกัน
  - **Durability** สำเร็จแล้วคงอยู่ถาวรแม้ไฟดับ
- NoSQL ส่วนใหญ่แลก ACID (โดยเฉพาะ C) กับความเร็วระดับ Big Data

> 💡 จำศัพท์: Cascade ไล่แก้ · Restrict อดแก้ · Redundancy ซ้ำซ้อน · Inconsistency ไม่ตรงกัน · Concurrency เข้าถึงพร้อมกัน · Backup กันหาย · Recover กู้คืน
