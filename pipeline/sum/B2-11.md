# บทที่ 11 IP Subnet, RAID, Partition และ File System
> บทเสริม (ไม่มีในเล่มน้ำตาล) · ออก: หา Network/Broadcast จาก IP, เลือก Subnet Mask ตามจำนวนเครื่อง, ความจุ RAID 0/1/5/6/10, MBR/GPT, FAT32/exFAT/NTFS

## 1. IP Subnet แบบบ้านเลขที่ ⭐⭐
- ให้มองเลขตัวสุดท้ายของ IP เป็น **บ้านเลขที่** ในซอย (0–255) และซอยถูกแบ่งเป็น **ช่วงขนาดเท่ากัน**
- ในแต่ละช่วง **บ้านหลังแรก = Network** (ชื่อวง) · **หลังสุดท้าย = Broadcast** (ประกาศถึงทุกเครื่อง) · **หลังตรงกลาง = IP ที่ให้เครื่องใช้ได้**

| Prefix | Subnet Mask | ขนาดช่วง | ใช้ได้กี่เครื่อง |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

- เลขหลัง / **เพิ่ม 1 → ขนาดช่วงหารครึ่ง** · ขนาดช่วง = **256 − เลข Mask** ในช่องที่ไม่ใช่ 255
- **จำนวนเครื่อง = ขนาดช่วง − 2** (หัก Network กับ Broadcast) ถ้านับเองให้ใช้ ตัวท้าย − ตัวแรก **+ 1**

## 2. วิธีหา Network / Broadcast 3 ขั้น ⭐⭐
1. ดูเลขหลัง / แปลงเป็น **ขนาดช่วง**
2. **เลขใน IP ÷ ขนาดช่วง** ปัดเศษทิ้ง แล้ว **คูณกลับ** = Network (หรือนับทีละขนาดช่วงจาก 0)
3. **Broadcast = Network ของช่วงถัดไป − 1** · ที่ใช้ได้คือตัวที่อยู่ระหว่างนั้น
- ตัวอย่าง **192.168.1.150/26** → ขนาด 64 → 150 ÷ 64 = 2.3 → 2 × 64 = **128** → ช่วง 128–191 → Network **.128** · Broadcast **.191** · ใช้ได้ .129–.190 = 62 เครื่อง
- ตัวอย่าง **10.0.0.200/28** → ขนาด 16 → 16 × 12 = **192** → ช่วง 192–207 → Network **.192** · Broadcast **.207** · ใช้ได้ .193–.206 = 14 เครื่อง
- ถ้า Prefix น้อยกว่า 24 (เช่น /20 = 255.255.**240**.0) ให้คิดที่ **ช่องที่ 3** แทน → 172.16.35.200/20 → ขนาด 16 → ช่วง 32–47 → Network **172.16.32.0** · Broadcast **172.16.47.255**
- ⚠️ ทริกตรวจคำตอบ: **Network เป็นเลขคู่ · Broadcast เป็นเลขคี่ · จำนวนเครื่องเป็นเลขคู่** เสมอ · ช้อยส์หลอกยอดฮิตคือ Broadcast ที่เกินไป 1 (เป็น Network ของช่วงถัดไป)

## 3. ต้องการ N เครื่อง ใช้ Mask อะไร ⭐⭐
- ต้องมีที่ **N + 2** แล้วเลือกขนาดช่วงที่เล็กที่สุดที่พอ
- 10 เครื่อง → 12 ที่ → ช่วง 16 → **/28** · 25 เครื่อง → ช่วง 32 → **/27** · 50 เครื่อง → ช่วง 64 → **/26** · 100 เครื่อง → ช่วง 128 → **/25**
- ⚠️ อ่านโจทย์ดีๆ: **"วงละ N เครื่อง"** คิดจาก 2ⁿ − 2 ≥ N · **"แบ่งเป็น N วง"** คิดจาก 2ⁿ ≥ N (ยืมบิต) เช่น /24 แบ่ง 6 วง → ยืม 3 บิต → **/27** (ได้ 8 วง วงละ 30 เครื่อง)

## 4. RAID ⭐⭐
| RAID | หลักการ | ดิสก์ขั้นต่ำ | ความจุใช้งาน | เสียได้ |
|---|---|---|---|---|
| 0 | Striping (ไม่มีสำรอง) | 2 | n × ขนาด | **0 ลูก** |
| 1 | Mirroring | 2 | 1 ลูก | 1 ลูก |
| 5 | Striping + Parity กระจาย | 3 | (n − 1) × ขนาด | 1 ลูก |
| 6 | Striping + Parity 2 ชุด | 4 | (n − 2) × ขนาด | 2 ลูก |
| 10 | Mirror เป็นคู่แล้ว Stripe | 4 | n ÷ 2 × ขนาด | อย่างน้อย 1 (คู่ละ 1) |

- ตัวอย่างดิสก์ 4 ลูก × 2 TB → RAID 0 = 8 · RAID 5 = 6 · RAID 6 = 4 · RAID 10 = 4 TB
- ดิสก์ **ต่างขนาด** คิดตาม **ลูกที่เล็กที่สุด** · RAID 5 ดิสก์ 4 ลูกใช้ได้ 75%
- RAID 10 ข้อมูลหายเมื่อ **ทั้ง 2 ลูกในคู่ Mirror เดียวกัน** เสีย · เหมาะกับฐานข้อมูลที่เขียนบ่อย (ไม่ต้องคำนวณ Parity)
- **Hot Spare** ดิสก์สำรองที่รอ Rebuild อัตโนมัติ · ⚠️ **RAID ไม่ใช่ Backup** ลบผิด/Ransomware เสียทุกสำเนา

## 5. Partition: MBR vs GPT ⭐
- เปรียบดิสก์เป็นที่ดิน · **Partition** = แบ่งแปลง (C:, D:) · **ตารางพาร์ทิชัน** = สมุดทะเบียน · **File System** = วิธีจัดของในแปลง

| | MBR | GPT |
|---|---|---|
| ขนาดดิสก์สูงสุด | **2 TB** | เกิน 2 TB ได้ |
| จำนวนพาร์ทิชัน | **Primary 4** (หรือ 3 + Extended ที่มี Logical) | **128** ใน Windows |
| คู่กับ | Legacy **BIOS** | **UEFI** (Windows 11 ต้องใช้) |

- GPT มีสำเนาตารางสำรองท้ายดิสก์และ CRC · เครื่องมือ Windows: **Disk Management** (diskmgmt.msc) / **diskpart**
- Linux นิยมแบ่ง / , /home และ **swap** (ทำหน้าที่คล้าย Page File)
- แบ่ง C: / D: ช่วยลง OS ใหม่ได้โดยไม่ลบ D: แต่ **ไม่ใช่ Backup** (ดิสก์เสีย หายทั้งคู่)

## 6. File System ⭐⭐
| | FAT32 | exFAT | NTFS |
|---|---|---|---|
| ไฟล์ละไม่เกิน | **4 GB** | แทบไม่จำกัด | แทบไม่จำกัด |
| เหมาะกับ | ทุกอุปกรณ์ (ทีวี/รถ) แฟลชเล็ก | แฟลช/SD ความจุสูง | ดิสก์ลง Windows |
| Windows / Mac | อ่านเขียนได้ | อ่านเขียนได้ | Mac อ่านอย่างเดียว |
| สิทธิ์ไฟล์ / เข้ารหัส | ไม่มี | ไม่มี | มี (ACL, EFS) |
| Journal | ไม่มี | ไม่มี | มี |


### ตารางรวม File System ทุกตัว
| File System | ของใคร / ปีที่เริ่มใช้ | ใช้กับ | จุดเด่นที่ต้องจำ | ข้อจำกัด |
|---|---|---|---|---|
| **FAT32** | Microsoft · 1996 | แฟลชไดรฟ์เล็ก ทีวี เครื่องเสียงรถ SD ≤ 32 GB | ใช้ได้กับแทบทุกอุปกรณ์ | ไฟล์ละไม่เกิน **4 GB** · Windows ฟอร์แมตได้ไม่เกิน 32 GB · ไม่มี Journal/สิทธิ์ไฟล์ |
| **exFAT** | Microsoft · 2006 | แฟลชไดรฟ์/SD ความจุสูง (SDXC) | ไฟล์ใหญ่ได้ · อ่านเขียนได้ทั้ง Win/Mac/Linux | ไม่มี Journal · ไม่มีสิทธิ์ไฟล์ |
| **NTFS** | Microsoft · 1993 | ดิสก์ที่ลง **Windows** | **Journal** · สิทธิ์ไฟล์ (ACL) · เข้ารหัส (EFS) · บีบอัด · Quota | Mac **อ่านได้อย่างเดียว** |
| **ReFS** | Microsoft · 2012 | **Windows Server** ที่เก็บข้อมูลจำนวนมาก, Hyper-V | **Checksum ตรวจข้อมูลเสีย** ซ่อมเองได้เมื่อใช้คู่กับ Storage Spaces · รองรับ Volume ใหญ่มาก | **บูต Windows ไม่ได้** · ไม่มี EFS/Quota · ใช้นอก Windows ไม่ได้ |
| **HFS+** (Mac OS Extended) | Apple · 1998 | **Mac รุ่นเก่า** (ก่อน macOS 10.13) | มี Journal | Windows อ่านเองไม่ได้ · ถูกแทนที่ด้วย APFS |
| **APFS** | Apple · 2017 | **Mac / iPhone รุ่นใหม่** (macOS 10.13+, iOS 10.3+) | ออกแบบมาสำหรับ **SSD** · **Snapshot** · Clone ไฟล์ทันที · เข้ารหัสในตัว · Copy-on-Write | Windows อ่านเองไม่ได้ |
| **ext4** | Linux · 2008 | **Linux** ส่วนใหญ่ (Ubuntu, Debian) | มี Journal · ไฟล์ละ 16 TB · Volume 1 EB | Windows/Mac อ่านเองไม่ได้ |
| **XFS** | SGI · 1994 | Linux Server (ค่าเริ่มต้นของ RHEL) | ทำงานกับไฟล์ใหญ่ได้เร็ว | ย่อขนาดพาร์ทิชันไม่ได้ |
| **Btrfs** | Linux · 2009 | Linux บางค่าย (Fedora, openSUSE) | Snapshot · Copy-on-Write · Checksum | ใช้นอก Linux ไม่ได้ |

### swap ไม่ใช่ File System
- **swap** คือพาร์ทิชัน (หรือไฟล์) ใน Linux ที่ใช้เป็น **หน่วยความจำเสมือน** เมื่อ RAM เต็ม ระบบจะย้ายข้อมูลที่ไม่ได้ใช้ใน RAM มาพักไว้ที่ swap
- เทียบได้กับ **pagefile.sys (Page File)** ของ Windows · ใช้ตอน Hibernate ด้วย
- ไม่ได้ใช้เก็บไฟล์ของผู้ใช้ · ถ้าเครื่องใช้ swap บ่อยจะช้า เพราะดิสก์ช้ากว่า RAM มาก → ควรเพิ่ม RAM

### จำง่ายๆ ตามค่าย
- **Microsoft:** FAT32 (เก่า ใช้ได้ทุกที่) → exFAT (แฟลชใหญ่) → NTFS (ดิสก์ Windows) → ReFS (Server)
- **Apple:** HFS+ (เก่า) → APFS (ใหม่ เน้น SSD)
- **Linux:** ext4 (ค่าเริ่มต้น) · XFS (Server) · Btrfs (Snapshot) · swap (หน่วยความจำเสมือน ไม่ใช่ File System)
- SD Card **SDHC ≤ 32 GB = FAT32** · **SDXC > 32 GB = exFAT**
- ⚠️ "ที่ว่างเหลือ 20 GB แต่ก๊อปไฟล์ 6 GB ไม่ได้" → เป็น **FAT32**
- `convert D: /fs:ntfs` แปลง FAT32 → NTFS **ข้อมูลไม่หาย** (แปลงกลับไม่ได้) · `format` ลบข้อมูลทั้งหมด
- **Quick Format** ล้างสารบัญ (ข้อมูลอาจกู้ได้) · **Full Format** สแกน Bad Sector ทั้งดิสก์ (ช้ากว่า)
- Cluster ใหญ่ → ไฟล์ใหญ่เร็วขึ้น แต่ไฟล์เล็กเปลืองพื้นที่ (Slack Space)
