# บทที่ 8 วิทยาการคำนวณ (Computing Science)

## 1. องค์ประกอบวิชาวิทยาการคำนวณ (น.295)
- **CS (Computer Science)** แก้ปัญหาเป็นขั้นตอน การเขียนโปรแกรม
- **ICT** รวบรวม ประมวลผล ค้นหา ประเมินความน่าเชื่อถือข้อมูล
- **DL (Digital Literacy)** ใช้เทคโนโลยีปลอดภัย รู้เท่าทันสื่อ กฎหมาย ลิขสิทธิ์
- ⚠️ "คณิตศาสตร์" ไม่ใช่องค์ประกอบ · หัวใจ = **Computational Thinking**

## 2. การคิดเชิงคำนวณ 4 องค์ประกอบ (น.296–298) ⭐
1. **Decomposition** แบ่งปัญหาใหญ่เป็นย่อย (เลเยอร์ Photoshop, แบ่งงานรายงานกลุ่ม, ปฏิรูป 11 ด้าน)
2. **Pattern Recognition** หารูปแบบที่ซ้ำ/คล้าย (ยุบโค้ดซ้ำเป็นฟังก์ชัน/ลูป, จัดหมวดสัตว์)
3. **Abstraction** แยกสิ่งสำคัญออกจากไม่สำคัญ (Google Maps แสดงแต่ถนน, ป้ายห้องน้ำ)
4. **Algorithm Design** ออกแบบขั้นตอนวิธี (Flowchart, IPO Chart, Pseudocode)

## 3. Python (น.298–299)
- ไม่ขึ้นกับแพลตฟอร์ม · **Open Source** · OOP · **Dynamic Typing** · Built-in: List, Dictionary, String · Tkinter (GUI) · จัดการหน่วยความจำอัตโนมัติ · ไลบรารี AI/ฐานข้อมูล/PDF

## 4. ข้อมูลและสารสนเทศ (น.299–302)
- ชนิดข้อมูล: ตัวเลข · อักขระ (13/2) · ภาพ · เสียง
- **ปฐมภูมิ** = เก็บจากแหล่งโดยตรง (สัมภาษณ์ สำรวจ บาร์โค้ด QR) · **ทุติยภูมิ** = ผู้อื่นรวบรวมไว้ (สถิติประชากรของรัฐ)
- ซอฟต์แวร์จัดการข้อมูล: ประมวลคำ (Word, Google Docs, Writer) · ตารางทำงาน (Excel, Calc, Sheets) · ฐานข้อมูล (Access) · นำเสนอ (PowerPoint, Impress, Slides) · กราฟิก (Photoshop, GIMP, Paint)

## 5. ภัยคุกคาม (Threat) (น.303–306)
- **Security** = ทำให้ข้อมูลรอดพ้นจากอันตรายทั้งตั้งใจและบังเอิญ
- การกระทำที่ทำให้เสียหาย = **Attack** · Hacker (คนดี) vs **Cracker** (คนไม่ดี)
- **ภัยทางกายภาพ (Physical)** ฮาร์ดแวร์เสีย น้ำท่วม ไฟไหม้ ฟ้าผ่า · **ภัยทางตรรกะ (Logical)** = Cyber Attack ต่อข้อมูล/ระบบ
- รูปแบบโจมตี: **Hacking Attacks** (เจาะเป้าหมายชัด) · **DoS** (ทำให้หยุดให้บริการ เช่น Mail Bomb, Worm) · **Malware Attacks** (หว่านไม่เจาะจง: Virus, Worm, Trojan, Spyware, Spam, Keylogger, Phishing, Sniffing)
- ป้องกัน 3 ระดับ: **บุคคล** (อัปเดตซอฟต์แวร์ · Antivirus · ระวังลิงก์ · รหัสซับซ้อน + **2FA**) · **องค์กร** (ซอฟต์แวร์ถูกลิขสิทธิ์ · Antivirus · ติดตามข่าวภัย · บล็อกเว็บอันตราย) · **รัฐบาล** (สร้างความตระหนัก · รับแจ้งความ · ความร่วมมือระหว่างประเทศ National Cyber Security Strategy)

## 6. องค์ประกอบระบบคอมพิวเตอร์ (ม.2) (น.306–309)
- ทำงาน: Input → แปลงเป็น 0/1 → CPU (เก็บชั่วคราวที่ RAM) → Output · ส่งผ่าน **Bus** · ทุกอย่างต่อบน **Mainboard**
- 5–6 องค์ประกอบ: **Hardware · Software · Peopleware · Data · Information · Procedure**
- Hardware 5 หน่วย: Input · CPU · Main Memory · Secondary Storage · Output
- **Peopleware 6 ด้าน**: **SA** (นักวิเคราะห์ระบบ สื่อกลางผู้ใช้–โปรแกรมเมอร์) · Programmer · User · **Operator** (เปิด/ปิด/เฝ้าระบบใหญ่) · **DBA** · **System Manager** (วางนโยบาย)
- Procedure = คู่มือ (User Manual, Operation Manual)

## 7. การพัฒนาแอปพลิเคชัน (ม.3) (น.309–317) ⭐
- ขั้นตอนทั่วไป: ศึกษาความต้องการ → **ออกแบบ (หัวใจ)** → ลงมือพัฒนา → ทดสอบ
- แอปเชิงพาณิชย์: **วางแผน** (คู่แข่ง · รายได้: in-app, subscription, โฆษณา, paid · การตลาด · Roadmap → **MVP** = Minimum Viable Product) → **ออกแบบ UX** (Wireframe, Workflow, Click-through) / **UI** (Style guide) → **เขียนโค้ด** → ปล่อยแอป → สังเกตและวัดผล
- Front-end: **Native** (แยกแพลตฟอร์ม เร็วสุด แพงสุด) · **Cross-platform** (React Native, Xamarin สายกลาง) · **Hybrid** (HTML/CSS/JS + Cordova/Ionic ถูกสุด ช้า)
- Back-end: ภาษา (Java, C#, Go, PHP, Python) · DB (SQL/NoSQL) · Hosting (AWS, Google Cloud, Azure) · Agile
- App Store: Apple ตรวจละเอียด **2–3 วัน** · Google Play **ไม่กี่ชั่วโมง**
- **SDLC**: Requirement → Design → Development → Testing → Maintenance (+ Planning & Monitoring)
- โมเดล: **Waterfall** (เส้นตรง) · **Agile** (วนรอบยืดหยุ่น) · **V-Model** (เน้นทดสอบทุกขั้น) · **Spiral** (วงกลมทำซ้ำ)
- **Software Release Life Cycle**: **Pre-alpha** (ต้นแบบ) → **Alpha** (ทดสอบภายในทีม) → **Beta** (ปล่อยผู้ใช้ภายนอกบางส่วน) → **RC** (Release Candidate) → **Stable/GA/RTM** → Maintenance
- อัปเดต: **Patch** (แก้บั๊ก/ความปลอดภัย) · Minor · Major · **EOL** (End of Life หยุดสนับสนุน)
- **Kanban (คัมบัง = ป้ายแสดง)**: บอร์ด **To do → Doing → Done** · การ์ดระบุงาน ความสำคัญ (critical/major/normal/minor) ประเภท (feature/bug) กำหนดเวลา ผู้รับผิดชอบ

## 8. IoT (น.317–319)
- วัตถุฝังวงจร ซอฟต์แวร์ **เซนเซอร์** + เชื่อมเครือข่าย → เก็บ/แลกเปลี่ยนข้อมูล ควบคุมจากระยะไกล
- **Smart Industry (Industry 4.0)** · **Smart City** (Smart Living, Governance, Mobility, People, Safety, Economy, Environment, Tourism, Farming) · Smart Life
- ประโยชน์: ข้อมูลแม่นยำ ลดต้นทุน · ความเสี่ยง: ถูกเจาะ/เรียกค่าไถ่ → ต้องมี IoT Security

## 9. Data Scientist (น.319–321)
- ผลลัพธ์ Data Science: ค้นพบสิ่งใหม่ · **Predictive Model** · **Data Product** · ช่วยตัดสินใจ
- หน้าที่: Define question → Collection → Understanding → **Preparation** → Processing/Modeling → วัดผล → **Visualization** → Optimization · ทำงานร่วม **Data Engineer**
- ทักษะ **Hard Skill**: Hacking (Programming, DB, Big Data) · Statistics & Math · Substantive Expertise · **Soft Skill**: Presentation, Data Visualization, ความรู้ธุรกิจ

## 10. การเรียงลำดับข้อมูล (ม.ปลาย) (น.322–324)
- **Internal Sorting** ข้อมูลพอดีหน่วยความจำหลัก · **External Sorting** ข้อมูลใหญ่เกิน ใช้ดิสก์/เทปช่วย
- **Selection Sort** หาค่าน้อยสุดในส่วนที่เหลือแล้วสลับมาไว้หน้า ทีละรอบ
- **Insertion Sort** หยิบทีละตัวแทรกในตำแหน่งที่ถูกในส่วนที่เรียงแล้ว (เหมือนเรียงไพ่ในมือ)
- (เสริม) **Bubble Sort** เปรียบเทียบคู่ติดกันแล้วสลับ ค่ามากลอยไปท้าย
