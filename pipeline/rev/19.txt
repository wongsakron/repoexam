B2-3-1-1|ข้อมูล (Data) คือข้อเท็จจริงของสิ่งต่างๆ ที่ยังไม่ผ่านการประมวลผล ส่วน Infographic และกราฟเป็นสารสนเทศ
B2-3-1-2|คลิปสรุปราคาเฉลี่ยเป็นผลจากการประมวลผลแล้ว จึงเป็นสารสนเทศ ส่วนวิดีโอ รูปภาพ และตารางน้ำหนัก-ส่วนสูงเป็นข้อมูลดิบ
B2-3-1-3|กราฟสรุปผลสอบผ่านการประมวลผลแล้ว จึงเป็นสารสนเทศ
B2-3-1-4|สารสนเทศ (Information) คือข้อมูลที่ผ่านการประมวลผลจนนำไปใช้ประโยชน์ได้
B2-3-1-5|ฐานข้อมูลคือแหล่งเก็บข้อมูลที่เกี่ยวข้องกัน รวมทั้งความสัมพันธ์ระหว่างข้อมูล
B2-3-1-6|NoSQL (Not Only SQL) คือฐานข้อมูลที่ไม่ใช่แบบเชิงสัมพันธ์ ส่วน MySQL เป็น RDBMS
B2-3-1-7|NoSQL ยืดหยุ่น เก็บได้ทั้งข้อมูลที่ไม่มีความสัมพันธ์และมีความสัมพันธ์ (ตามแนวของเล่ม) และ NoSQL ไม่ได้มีมาตรฐานเดียว
B2-3-1-8|Horizontal Scaling คือขยายระบบด้วยการเพิ่มจำนวนเซิร์ฟเวอร์ ส่วนการอัปเกรดเครื่องเดิมคือ Vertical Scaling
B2-3-1-9|NoSQL ได้รับความนิยมเพราะเก็บข้อมูลได้ยืดหยุ่น ไม่ต้องกำหนดโครงสร้างตายตัว
B2-3-1-10|RDB มีโครงสร้าง (Schema) ตายตัว และมีกฎเกณฑ์เคร่งครัด
B2-3-1-11|จุดเด่นของ NoSQL คือรองรับข้อมูลขนาดใหญ่ระดับ Big Data ได้ดี
B2-3-1-12|Data Model คือรูปแบบการจัดเก็บ เรียกใช้ และแลกเปลี่ยนข้อมูล เช่น Key-Value, Document, Graph และ Wide-Column
B2-3-1-13|RDB เก็บข้อมูลเป็นตาราง (Relation) ที่มีแถวและคอลัมน์
B2-3-1-14|NoSQL กระจายเก็บข้อมูลได้หลายเครื่อง (Distributed) และเข้าถึงได้เร็ว จึงเหมาะกับ Big Data
B2-3-1-15|Key-Value เก็บข้อมูลชิ้นเล็กจำนวนมากเป็นคู่คีย์กับค่า เช่น Redis
B2-3-1-16|Document Database เก็บข้อมูลเป็นเอกสาร JSON ที่มีลำดับชั้น (Hierarchy) เช่น MongoDB
B2-3-1-17|Wide-Column เก็บข้อมูลเป็นคีย์และกลุ่มคอลัมน์ เช่น Cassandra และ HBase
B2-3-1-18|ความสัมพันธ์ระหว่างผู้ใช้ใน Social Media เหมาะกับ Graph Database (โหนดคือคน และเส้นคือความสัมพันธ์)
B2-3-1-19|การหาเส้นทางในแผนที่ใช้ Graph คือสถานที่เป็นจุดและถนนเป็นเส้นเชื่อม
B2-3-1-20|ใน Graph สถานที่คือ Node และระยะทาง/เส้นทางคือ Edge
B2-3-1-21|In-Memory Database เก็บข้อมูลใน RAM จึงอ่านเขียนเร็วที่สุด
B2-3-1-22|RDB ใช้ภาษา SQL จัดการข้อมูล ส่วน MySQL เป็นชื่อซอฟต์แวร์ DBMS
B2-3-1-23|รีเลชันคือตาราง ไม่ใช่ทั้งฐานข้อมูล ข้อ ค จึงไม่ใช่ความหมายเดียวกัน ส่วนข้ออื่นเป็นคำพ้องกันจริง (แถว = ทูเพิล = ระเบียน, คอลัมน์ = แอททริบิวต์ = ฟิลด์)
B2-3-1-24|ตามแนวของเล่ม ข้อมูลที่ Insert เพิ่มเข้าไปจะต่อท้ายตาราง ส่วนการลบข้อมูลใช้ DELETE ไม่ใช่ INSERT
B2-3-1-25|ข้อมูลที่เพิ่มต้องตรงกับชนิดและขนาดที่คอลัมน์กำหนด และคีย์หลักห้ามซ้ำ
B2-3-1-26|16 bit = 2 byte ซึ่งเล็กกว่า 16 byte และตัวอักษร 2 ตัวในระบบ Unicode (เช่น ภาษาไทย) อาจใช้มากกว่า 2 byte (ตามแนวของเล่ม)
B2-3-1-27|ลำดับจากเล็กไปใหญ่: Bit < Byte < Field < Record < File/Table < Database
B2-3-1-28|ความสัมพันธ์ใน RDB มี 3 แบบ คือ 1:1, 1:M และ M:N ไม่มี Zero to Many
B2-3-1-29|ณ เวลาหนึ่ง โรงเรียนหนึ่งมีผู้อำนวยการหนึ่งคน และผู้อำนวยการหนึ่งคนบริหารหนึ่งโรงเรียน จึงเป็น 1:1
B2-3-1-30|แฟน (หนึ่งคน) มีกิ๊กได้หลายคน จึงเป็น One to Many (ตามมุกของเล่ม)
B2-3-1-31|การ์ด Ethernet หนึ่งใบมี MAC Address เฉพาะหนึ่งค่า จึงเป็น 1:1
B2-3-1-32|ครูที่ปรึกษาหนึ่งคนดูแลนักเรียนหลายคน และนักเรียนแต่ละคนมีครูที่ปรึกษาคนเดียว จึงเป็น 1:M
B2-3-1-33|ครูหนึ่งคนสอนลูกศิษย์หลายคน และนักเรียนหนึ่งคนเรียนกับครูหลายคน จึงเป็น M:N
B2-3-1-34|วิชาหนึ่งมีนักศึกษาหลายคน และนักศึกษาหนึ่งคนเรียนหลายวิชา จึงเป็น M:N
B2-3-1-35|สินค้าหนึ่งชิ้นมีสมาชิกซื้อได้หลายคน และสมาชิกหนึ่งคนซื้อสินค้าได้หลายชิ้น จึงเป็น M:N
B2-3-1-36|ชนิดข้อมูลและความยาวสูงสุดกำหนดที่ Attribute (คอลัมน์)
B2-3-1-37|Record (ระเบียน/แถว) รวมข้อมูลหลายฟิลด์ต่างชนิดกันของสิ่งหนึ่งไว้ด้วยกัน
B2-3-1-38|View คือตารางเสมือนที่ดึงข้อมูลจากตารางต่างๆ มาแสดงให้ผู้ใช้
B2-3-1-39|Key ใช้ระบุทูเพิล (แถว) แต่ละแถวไม่ให้ซ้ำกัน
B2-3-1-40|ตารางหนึ่งมี Primary Key ได้เพียงหนึ่งชุด (อาจประกอบจากหลายคอลัมน์ได้ เรียกว่า Composite Key)
B2-3-1-41|Primary Key ใช้ระบุแถวเพื่อค้นหาหรือจัดการข้อมูลแถวนั้น
B2-3-1-42|Foreign Key เชื่อมความสัมพันธ์ไปยัง Primary Key ของตารางอื่น
B2-3-1-43|Candidate Key ที่ไม่ได้ถูกเลือกเป็น Primary Key เรียกว่า Alternate Key (คีย์คู่แข่ง/คีย์สำรอง)
B2-3-1-44|Static Integrity คือกฎความถูกต้องที่คงที่ เช่น หนึ่งวันมี 24 ชั่วโมงเสมอ
B2-3-1-45|Dynamic Integrity คือความถูกต้องเมื่อข้อมูลเปลี่ยนสถานะตามลำดับเหตุการณ์ เช่น นางสาว → นาง (เมื่อแต่งงาน) และอาจกลับเป็นนางสาว (เมื่อหย่า) ได้
B2-3-1-46|Data Independence คือเปลี่ยนโครงสร้างข้อมูลได้โดยไม่กระทบโปรแกรมที่เรียกใช้
B2-3-1-47|Physical Data Independence คือเปลี่ยนวิธีจัดเก็บทางกายภาพได้โดยไม่กระทบโปรแกรม
B2-3-1-48|Logical Data Independence คือเปลี่ยนโครงสร้างเชิงตรรกะ (ความสัมพันธ์/Schema) ได้โดยไม่กระทบโปรแกรม
B2-3-1-49|Soft Crash คือระบบล่มที่ข้อมูลในหน่วยความจำหายแต่ดิสก์ไม่เสียหาย เช่น ไฟดับ
B2-3-1-50|Hard Crash คืออุปกรณ์เก็บข้อมูลเสียหาย เช่น ฮาร์ดดิสก์ชำรุด ทำให้ข้อมูลบนดิสก์สูญหาย
B2-3-1-51|Concurrency Control ควบคุมการเข้าถึงข้อมูลพร้อมกันของผู้ใช้หลายคน ไม่ให้ข้อมูลผิดพลาด
B2-3-1-52|Deadlock (วงจรอับ) คือหลายรายการรอทรัพยากรที่อีกฝ่ายถือไว้ จนไม่มีใครทำงานต่อได้
B2-3-1-53|RDB นิยมขยายแบบแนวตั้ง (Vertical) คืออัปเกรดเครื่องให้แรงขึ้น
B2-3-1-54|ไฟล์เดียวกันเก็บซ้ำหลายที่คือข้อมูลซ้ำซ้อน (Data Redundancy)
B2-3-1-55|ถ้าแก้ไขไม่ครบทุกที่ ข้อมูลแต่ละที่จะไม่ตรงกัน (Data Inconsistency)
B2-3-1-56|การปรับปรุงข้อมูลที่มีความสัมพันธ์ใช้ Cascade, Restrict, No Action หรือ Set Null ไม่มี "Act"
B2-3-1-57|ถ้าแก้ไขโดยไม่สนความสัมพันธ์กับตารางอื่น ข้อมูลที่เกี่ยวข้องจะขัดแย้งกัน (Inconsistency)
B2-3-1-58|DBMS เป็นซอฟต์แวร์ตัวกลางระหว่างผู้ใช้/โปรแกรมกับฐานข้อมูล ส่วน DBA คือบุคคลผู้ดูแล
B2-3-2-1|ข้อมูลในฐานข้อมูลคือข้อเท็จจริงที่สนใจและถูกจัดเก็บในรูปแบบดิจิทัล
B2-3-2-2|สารสนเทศคือผลลัพธ์จากการประมวลผลข้อมูล
